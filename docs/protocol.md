# 通信メッセージ仕様

プロトコルバージョン: 2
チャンネル名: `radiomod:main`

## 基本ルール

- 向きは、サーバー → mod（S→C）と、mod → サーバー（C→S）の2つ。
- 先頭の1バイトがメッセージ種別（符号なし）。mod 側は、Forge の SimpleChannel を使わず、先頭の1バイトも含む生のペイロードを自分で読み書きする（NetworkRegistry.newEventChannel）。SimpleChannel を使う場合は、先頭に付くディスクリミネータの値を、種別の値（0x01・0x80 など）と同じにして、重ならないようにする。
- 数値は big-endian。`long` は8バイト、`int` は4バイト、`double` は8バイト、`float` は4バイト。
- 文字列は、2バイト（符号なし）のバイト数 + UTF-8 の本体。長さの上限は、url が2048バイト、title と detail が256バイト。title と detail は超えたら切り詰める。url が上限を超えたら送らない。
- 「サーバー時刻」は、サーバーの `System.currentTimeMillis()`（ミリ秒）。時刻を持つ項目は、全てこの時計の値。
- 受け取り側は、未知の種別・長さ不足のメッセージを無視して、警告をログに出す。例外で止まってはいけない。

## スロット

音の出どころを表す。各スロットは同時に1曲だけ再生する。同じスロットに新しい `PLAY` が届いたら、前の曲をすぐ止めて置き換える。

| 並び | 型 | 内容 |
| --- | --- | --- |
| slotType | byte | 0 = 個人、1 = 共有、2 = ラジオ |
| ラジオID | long, long | slotType が 2 のときだけ続く（UUID の上位64ビット、下位64ビット） |

以降、メッセージ表の「スロット」は、この並び全体を指す。

## サーバー → mod

| 種別 | 名前 | 並び |
| --- | --- | --- |
| 0x01 | PLAY | スロット / trackId(long) / url / title / durationMs(long、ライブは -1) / originMs(long) / ラジオのときだけ: dimension(文字列、例 `minecraft:overworld`) / x,y,z(double×3) / range(float) |
| 0x02 | PAUSE | スロット / positionMs(long) |
| 0x03 | RESUME | スロット / originMs(long) |
| 0x04 | STOP | スロット |
| 0x05 | SYNC | スロット / originMs(long) |
| 0x06 | MOVE | スロット（ラジオ） / dimension(文字列) / x,y,z(double×3) |
| 0x07 | TIME | clientNanos(long) / serverNowMs(long) |
| 0x08 | QUEUE | スロット / label(文字列。ラジオのときは名前、それ以外は空) / state(byte、0 = 停止、1 = 再生中、2 = 一時停止) / loop(byte、0 = なし、1 = 単曲、2 = 全体) / index(int、いま何曲目か。キューが空なら -1) / count(int、最大 200) / count 個の { title(文字列) / durationMs(long、ライブは -1) } |
| 0x09 | OPEN | スロット |

- `originMs` は、曲の頭（位置0ms）に当たるサーバー時刻。鳴らすべき位置は、「いまのサーバー時刻」から `originMs` を引いた値になる。
- `positionMs` は、一時停止した位置（曲の頭からのミリ秒）。
- `QUEUE` は、プレーヤー画面に出すキューの状態。`OPEN` の直後と、`CONTROL` の返事として、操作した1人にだけ送る。曲が200を超えるときは、先頭の200曲だけを送る。
- `OPEN` は、そのスロットのプレーヤー画面を開く指示（`/ps popup`・`/ps all popup`・`/rp <名前> list popup`）。

## mod → サーバー

| 種別 | 名前 | 並び |
| --- | --- | --- |
| 0x80 | HELLO | protocolVersion(int) / modVersion(文字列) |
| 0x81 | ERROR | スロット / trackId(long) / reason(byte) / detail(文字列) |
| 0x82 | TIME_REQ | clientNanos(long) |
| 0x83 | CONTROL | スロット / action(byte) / arg(int) |

reason: 0 = 取得に失敗、1 = 非対応のURL、2 = デコードに失敗、3 = その他。

CONTROL の action: 0 = PAUSE（一時停止と再開の切り替え）、1 = SKIP、2 = PREVIOUS、3 = STOP（止めてキューを空にする。共有は、自分が聞くのをやめるだけ）、4 = JUMP（arg の番号の曲を最初から再生。0 始まり）、5 = LOOP（なし → 単曲 → 全体 → なし の順に切り替え）、6 = REFRESH（`QUEUE` を返してもらう）、7 = SEEK（再生位置を arg のミリ秒に動かす。ライブには効かない）。arg は JUMP（曲の番号）と SEEK（位置）のときだけ使い、それ以外は 0。
SEEK を受けたサーバーは、位置を飛ばせない `SYNC` の代わりに、同じ曲の `PLAY` を、動かし先から鳴る新しい `originMs` で送り直す（一時停止中なら、そのあとに `PAUSE` も送る）。
サーバーは、スロットに応じて、`/ps`・`/ps all`・`/rp` と同じ権限を確かめてから実行する。権限がないときや、共有を聞いていないときは、何もしない。

## 時計合わせ

mod が「いまのサーバー時刻」を推定するための手順。

1. mod は、送る直前の `System.nanoTime()` を `clientNanos`（t0）として、`TIME_REQ` を送る。
2. サーバーは、`TIME_REQ` を処理した時点で、`clientNanos` をそのまま返し、その時点のサーバー時刻を `serverNowMs` に入れて `TIME` を返す。間に、ほかの処理を挟まない。
3. mod は、`TIME` を受け取った時点の `System.nanoTime()` を t1 とする。往復時間は t1 - t0。サーバー時刻とのずれ（offset）は、serverNowMs - (t0 + t1) / 2 を、ミリ秒にそろえて求める。
4. 直近8回の結果のうち、往復時間がいちばん短いものの offset を採用する（サーバーの処理は tick に合わせて遅れることがあるので、遅れの小さい結果だけを使う）。採用した offset は、一度に5msまでしか変えない（鳴らすべき位置が急に動かないようにするため）。
5. 回数は、接続直後（`HELLO` のあと）に100ms間隔で8回。そのあとは30秒ごとに1回。
6. 「いまのサーバー時刻」の推定値は、自分の `System.nanoTime()` をミリ秒にしたものに、offset を足した値。

## 手順とルール

1. 接続: mod は、サーバーに入った直後に `HELLO` を送る。サーバーは、`HELLO` を受けたプレイヤーを「mod 導入済み」と記録する。`HELLO` の前には何も送らない。切断したら記録を消す。
2. 状態の送信: `HELLO` を受けたサーバーは、そのプレイヤーの個人再生が再生中なら、いまの `originMs` で `PLAY` を送る。一時停止中なら `PLAY` のあとに `PAUSE` を送る。再生中のラジオには、全て同じように送る。
3. 再生の始め方: サーバーが曲を新しく始めるときは、`originMs` を「そのときのサーバー時刻 + start-lead-ms（初期値 500）」にして `PLAY` を送る。`RESUME` の `originMs` は、「再開するときのサーバー時刻 + start-lead-ms - 止まっていた位置」。mod は、鳴らすべき位置が負のあいだは無音で待ち、0になった時点で鳴らし始める。準備が間に合わなかったときは、鳴らすべき位置まで進めてから鳴らす。
4. ずれの補正: mod は、実際に鳴っている位置（再生済みのサンプル数から計算する）と、鳴らすべき位置との差を、約1秒ごとに計算する。再生中に、音が飛んだり戻ったりしてはいけない。補正は、再生速度の微調整だけで行う。差が40ms以上になったら補正を始め、10ms未満になったらやめる。速度は最大 ±2% で、急に変えず、滑らかに変える（遅れているときは速く、進んでいるときは遅く）。
   位置を合わせ直してよいのは、音がすでに止まっていて、聞こえる音が飛ばないときだけ。曲を始めるとき、一時停止から再開するとき、ラジオの範囲に入ったとき、取得が途切れて音が止まったあとに再開するとき。
5. `SYNC`: サーバーは、設定の間隔（初期値 30秒）で、各スロットの `originMs` を再送する。mod は、新しい `originMs` に切り替える。普通は同じ値が届く。切り替えても位置は飛ばさず、補正の目標だけを変える。
6. 曲の終わり: サーバーが、「`originMs` + `durationMs`」を過ぎたと判断して、次の `PLAY` を送る。次の `originMs` は、3の手順で新しく作る。mod は、曲の終わりをサーバーに知らせない。次の `PLAY` が来るまで、mod は無音で待つ。
7. エラー: mod は、取得や再生に失敗したら `ERROR` を送って、そのスロットを無音にする。サーバーは、その曲をスキップして次へ進む。
8. 個人再生の一時停止: プレイヤーが共有を聞き始めたとき、サーバーは個人スロットへ `PAUSE` を送る。聞くのをやめたときは `RESUME` を送る。
9. ラジオの範囲: 距離の計算は mod が行う。範囲の外では取得を止め、範囲に入ったら、`originMs` から計算した位置から再開する。
10. 別の次元: プレイヤーがラジオの dimension と違う次元にいるあいだは、そのラジオを鳴らさない。
11. 位置を合わせられない音源: ライブ（`durationMs` が -1）と、位置の合わせ直しができない音源は、`originMs` による位置合わせも、4の補正もしない。各自が取得した時点から鳴らす。
12. 出力機器の遅れ: mod は、プレイヤーが設定した手動の補正値（ms）を、鳴らすべき位置に足す。Bluetooth ヘッドホンなど、出力の遅れが大きい機器のため。
13. バージョン違い: `HELLO` の protocolVersion がサーバーと違うとき、サーバーはそのプレイヤーに何も送らず、ログに警告を出す。
14. プレーヤー画面: mod は、画面を開いている間、約1秒ごとに `REFRESH` を送り、返ってきた `QUEUE` で画面を更新する。`QUEUE`・`REFRESH` は量が多いので、サーバーはログに出さない（debug-net のときだけ）。`OPEN` や `CONTROL` の `PAUSE` などの操作は、画面を持たない mod には何も起きない（未知の種別は無視する）。
