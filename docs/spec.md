# Minecraft 1.20.1 ラジオ/音楽再生 Mod＋Plugin 仕様書

Oct 31, 2026 · @おおがた

## 1. 概要と前提

Minecraft 1.20.1 で、URLの音楽・プレイリストをサーバー全体、または設置したラジオごとに同期再生する。Forge mod（クライアント）が音を鳴らし、Spigot plugin（サーバー）が状態管理とコマンドを担当する。

| 項目 | 内容 |
| --- | --- |
| 名前・作者 | mod は `radiomod`、plugin は `radioplugin`、作者は `oogata` |
| 対象バージョン | Minecraft 1.20.1 / Java 17 |
| Mod | Forge 47.x（クライアント必須、サーバーには入れない想定） |
| Plugin | Spigot API 1.20.1（Paper でも動作すること） |
| コマンド1 | `/playersound`（短縮 `/ps`）: 自分だけに再生する。`all` で再生を共有できる。聞くかどうかは各プレイヤーが選ぶ |
| コマンド2 | `/radiodisplay`（短縮 `/rd`）: ラジオの設置・管理 |
| コマンド3 | `/radioplayer`（短縮 `/rp`）: ラジオ単位の再生 |
| 見た目 | ブロックではなく、BDEngine で作った Display Entity のモデル |

mod を入れていないプレイヤーは音が聞こえないだけで、サーバーには普通に参加できる。コマンドの実行はサーバー側 plugin だけで完結する。

### 用語と入力ミスの解釈

依頼文の綴りゆれは次のとおり解釈した。違っていたらコメントで指摘してほしい。

- `sotp` は `stop` のこと
- `/rd` と `/rp` は、それぞれ `/radiodisplay` と `/radioplayer` の短縮形
- `Previous` は小文字の `previous` に統一する
- サブコマンドは大文字小文字を区別しない

## 2. 全体アーキテクチャ

再生状態（キュー・位置・loop・一時停止）はサーバーの plugin だけが持ち、mod はその状態に合わせて音を鳴らすだけにする。

矢印は情報の流れ。サーバーは長さやタイトルの取得にだけ音源へアクセスし、音声そのものは各クライアントが取りに行く。

### 通信

- チャンネル名は `radiomod:main`（仮）。plugin → mod は Spigot の Plugin Messaging（`Player#sendPluginMessage`）で送る。
- mod は接続時に `HELLO`（mod バージョン）を送る。plugin はこれで mod 導入済みのプレイヤーを記録し、未導入者には何も送らない。
- Forge 1.20.1 の通信チャンネルが Spigot サーバーとやり取りできるかを、実装の最初（フェーズ1）に検証する。バージョン照合は常に受け入れる設定にする。

### メッセージ（概念仕様）

| 向き | 名前 | 内容 |
| --- | --- | --- |
| サーバー → mod | `PLAY` | トラックURL・タイトル・長さ・再生の基準時刻（サーバー時刻）・再生対象（そのプレイヤー個人／共有／ラジオID＋座標） |
| サーバー → mod | `PAUSE` | 止まった位置（ms） |
| サーバー → mod | `RESUME` | 再開の基準時刻（サーバー時刻） |
| サーバー → mod | `STOP` | 再生の停止と破棄 |
| サーバー → mod | `SYNC` | 基準時刻の定期的な再通知 |
| サーバー → mod | `MOVE` | ラジオの新しい座標 |
| サーバー → mod | `TIME` | 時計合わせの返事（サーバーの現在時刻） |
| mod → サーバー | `HELLO` | mod バージョン |
| mod → サーバー | `TIME_REQ` | 時計合わせの問い合わせ |
| mod → サーバー | `ERROR` | トラックID・理由（取得失敗・非対応URLなど） |

### 同期の方針

- 目標は、プレイヤー同士の再生位置のずれを 100ms 以内に収めること（初期値案）。
- 再生中に、音が飛んだり、少し前に戻ったりしてはいけない。ずれの補正は、再生速度の微調整だけで行う。
- 位置は、「曲の頭に当たるサーバー時刻」（基準時刻）で表す。各 mod は、サーバーとの時計のずれを測って、「いまのサーバー時刻」を自分で推定し、基準時刻との差を、鳴らすべき位置にする。ネットワークの遅れに左右されない。
- 時計合わせは、mod が `TIME_REQ` を何回か送り、往復時間がいちばん短かった結果を採用する。接続直後に8回、そのあとは30秒ごとに1回。採用した時計のずれは、一度に5msまでしか変えない（鳴らすべき位置が急に動かないようにするため）。
- 再生を始めるとき、サーバーは基準時刻を少し先（初期値 500ms）にして `PLAY` を送り、全員が同時に始められるようにする。準備が間に合わなかった mod は、鳴らすべき位置まで進めてから鳴らし始める。
- ずれの補正は、mod が、実際に鳴っている位置と鳴らすべき位置を比べて行う。差が40ms以上になったら補正を始め、10ms未満になったらやめる。再生速度は最大 ±2% で、急に変えず、滑らかに変える（遅れているときは速く、進んでいるときは遅く）。
- 位置を合わせ直してよいのは、音がすでに止まっていて、聞こえる音が飛ばないときだけ。曲を始めるとき、一時停止から再開するとき、ラジオの範囲に入ったとき、取得が途切れて音が止まったあとに再開するとき。
- 一時停止からの再開、途中参加、`SYNC` でも、同じ基準時刻の仕組みを使う。`SYNC` で基準時刻が変わっても、位置は飛ばさず、補正の目標だけを変える。
- 限界: Bluetooth ヘッドホンなど、音の出力の遅れは測れない。mod の設定で、プレイヤーが手動の補正値（ms）を足せるようにする。ライブ配信（インターネットラジオ）は、位置の同期ができない。

## 3. 再生の共通仕様

`/ps` と `/rp` は同じ再生エンジンを使い、違いは再生の対象（プレイヤー個人か、ラジオ1台か）だけにする。再生エンジンは、プレイヤーごと・ラジオごとに独立した状態を持つ。

### 再生状態

| 項目 | 内容 |
| --- | --- |
| キュー | トラックの一覧（URL・タイトル・長さ）。長さが不明なものはライブ配信扱い |
| 現在のトラック | キュー内の位置（インデックス） |
| 再生位置 | ミリ秒。サーバーが管理する |
| 状態 | 停止中 / 再生中 / 一時停止中 |
| loop | なし / 単曲 / プレイリスト全体 |

### 対応するURL

| 種類 | 扱い |
| --- | --- |
| mp3・aac・ogg・wav などの直リンク | 対応 |
| インターネットラジオ（Icecast・Shoutcast） | 対応。ライブ扱いなので skip・previous・単曲 loop は無効で、再生位置の同期もできない（各自が接続した時点の音が流れる） |
| YouTube（動画・プレイリスト） | 対応。youtube-source などの追加ライブラリが必要で、規約上の注意あり |
| SoundCloud・Bandcamp | LavaPlayer 標準の対応範囲で任意対応 |

上の表にないURLは、「非対応のURLです」と表示する。

### 再生ルール

- loop は、`play` に付けた場合は単曲、`playlist` に付けた場合はプレイリスト全体を繰り返す。
- トラックが終わると次へ進む。最後のトラックが終わった場合は、loop なしなら停止（キューは残す）、プレイリスト全体 loop なら先頭へ戻る。
- `skip` は次のトラックへ進む。最後のトラックで loop なしの場合は停止する。
- `previous` は1つ前のトラックを最初から再生する。先頭のトラックでは、そのトラックを最初から再生し直す。
- `pause` は再生中なら一時停止、一時停止中なら再開する。停止中は何もせず、その旨を表示する。
- `stop` は再生を止めてキューを空にし、loop も解除する。
- 取得に失敗したトラック（mod から `ERROR` が届いたもの）は自動でスキップする。連続3回失敗したら停止する（初期値案）。
- 再生が始まったら、タイトルをその曲が聞こえるプレイヤーへ通知する。通知先（チャット・アクションバー・なし）は設定で選べる。
- 音量は、mod が Minecraft の「音とサウンド設定」画面に専用のスライダーを足して調整する。スライダーは「音楽（`/ps`）」と「ラジオ」の2本で、ジュークボックス／ノートブロックの音量とは別にする。
- 画面への追加は Forge のイベントで行う。ほかの mod がその画面を作り替えていて表示がずれる場合に備え、mod の設定画面からも同じ値を変えられるようにする。

## 4. /playersound（/ps）

`/ps` は、コマンドを打ったプレイヤー自身だけに音楽を流す。再生状態（キュー・位置・loop）はプレイヤーごとに別々に持つ。`all` を付けると、その再生を「共有」として公開する。共有が始まると、ほかのプレイヤーにチャットでお知らせが届き、聞くかどうかは各プレイヤーが選ぶ。共有した再生は、`/ps all` のあとにサブコマンドを付けて操作する（例: `/ps all skip`）。

| 構文 | 動作 |
| --- | --- |
| `/ps play <URL>` | キューを空にして、そのURLを1曲として再生する |
| `/ps play <URL> loop` | 同じ曲を繰り返し再生する（単曲 loop） |
| `/ps play` | 現在のトラックを最初から再生する。キューが空なら「再生できる曲がありません」と表示 |
| `/ps playlist <URL>` | プレイリストのURLを展開し、先頭から順番に再生する |
| `/ps playlist <URL> loop` | プレイリスト全体を繰り返し再生する |
| `/ps add <URL>` | そのURLの曲を、今のキューの後ろに足す。プレイリストのURLなら、中身を順番に足す。キューが空か停止中なら、足した曲から再生を始める |
| `/ps pause` | 一時停止と再開を切り替える |
| `/ps stop` | 再生を止め、キューを空にする |
| `/ps list` | 現在のキューをチャットに表示する |
| `/ps list score` | 現在のキューをスコアボード（サイドバー）に表示する |
| `/ps skip` | 今の曲をスキップして次の曲を再生する |
| `/ps previous` | 1つ前の曲を再生する |
| `/ps all` | 自分の今の再生（キュー・位置・loop）を、共有の再生として始める。オンラインのほかのプレイヤーに、聞くかどうかを選べるお知らせを出す。すでに共有がある場合は、自分の再生で置き換える |
| `/ps all <サブコマンド>` | 共有の再生を操作する。`play`・`playlist`・`add`・`pause`・`stop`・`list`・`list score`・`skip`・`previous` が使え、`loop` の付け方も含めて `/ps` の同名サブコマンドと同じ動きで、対象が共有の再生になる。`/ps all stop` は共有を終える |
| `/ps listen` | 共有されている再生を聞く。今の再生位置から鳴り、続きの曲も流れる |
| `/ps leave` | 共有を聞くのをやめる。共有そのものは続き、あとで `/ps listen` でまた聞ける |

### 入力と表示の細部

- サブコマンドは Tab 補完に対応する。`loop` は URL の後ろだけで補完される。
- URL は `http` または `https` のみ受け付ける。それ以外は使い方を表示して終了する。
- `list` は番号・タイトル・長さを並べ、再生中の曲に印を付ける。ライブ配信は「LIVE」と表示する。
- `list score` はコマンドを実行したプレイヤーだけに表示する。もう一度実行すると消える。サイドバーの上限（15行）に合わせて、再生中の曲の前後を中心に表示し、長いタイトルは切り詰める。
- 共有の再生は、サーバーに1つだけの独立した再生状態。`/ps all` を実行した時点の自分の再生の中身がコピーされ、その後は自分の個人再生とは別に進む。
- 共有を始めた人も、聞く側として扱う。共有を始めたら、自分の個人再生は一時停止する。
- 共有のお知らせ: 共有が始まると（`/ps all` でも、共有がないときの `/ps all play <URL>` でも）、ほかのオンラインのプレイヤー（mod 導入済み）のチャットに「◯◯さんが音楽を共有しています: 曲名」と、［聞く］［聞かない］のボタンが出る。ボタンは、クリックで `/ps listen` と `/ps leave` を実行する。
- お知らせを無視したプレイヤーは、聞かない状態のまま。共有が始まったあとにサーバーへ参加したプレイヤーにも、同じお知らせを出す。
- 聞いているプレイヤーは、いつでも `/ps leave` でやめ、`/ps listen` でまた聞ける。やめても、共有そのものは続く。
- 共有の再生を操作できるのは、共有を聞いているプレイヤー（共有を始めた人を含む）。操作は `/ps all <サブコマンド>` で行い、誰が操作しても、聞いている全員に反映される。
- 共有がないときの `/ps all play`・`/ps all playlist`・`/ps all add` は、新しく共有を始める。それ以外の `/ps all <サブコマンド>` は、「共有している再生がありません」と表示する。
- `/ps <サブコマンド>`（`all` なし）は、いつも自分の個人再生に対する操作。
- 共有を聞いている間に、`play`・`playlist`・`add`・`pause`・`stop`・`skip`・`previous`（どれも `all` なし）を打つと、確認を出す。「共有を聞いています。聞くのをやめて、自分の再生を実行しますか？」と表示し、［やめて実行］［キャンセル］のボタンを付ける。
- ［やめて実行］は `/ps confirm` を実行する。`/ps leave` と同じ共有を聞くのをやめる処理をしてから、打った操作を自分の個人再生に対して行う。［キャンセル］は `/ps cancel` を実行し、何も変えない。確認は一定時間（初期案: 30秒）で無効になる。confirm と cancel は Tab 補完の候補に出さず、ボタンからだけ使う。共有そのものは、ほかの人のために続く。権限は `radioplugin.ps` と同じ。
- `list` と `list score` は表示だけなので、聞いている間でも確認なしでそのまま実行する。
- 共有を聞くのをやめたとき（`/ps leave`、または共有の終了）は、一時停止していた個人再生を、止まった位置から再開する。確認から続けて実行した操作がある場合は、その操作の結果を優先する。
- 共有が終わったとき（`/ps all stop`、聞いている人が1人もいなくなった、別の人が `/ps all` で置き換えた）は、聞いていた人に知らせて、聞く状態を解除する。次の共有は、また許可が要る。
- 共有できるのは同時に1つ。
- 操作の結果は実行者のチャットに返す。曲名の通知は、その曲が聞こえるプレイヤーに出す。

## 5. ラジオの設置と管理（/radiodisplay・/rd）

ラジオは、杖で選んだ場所に Display Entity の組み合わせで作る置物として設置する。ブロックではなくエンティティなので、mod を入れていないプレイヤーにも同じ見た目で見える。

| 構文 | 動作 |
| --- | --- |
| `/rd wand` | 設置用の杖を受け取る |
| `/rd create <名前>` | 杖で選んだ場所にラジオを設置する |
| `/rd delete <名前>` | ラジオを撤去する。再生中なら止めてから消す |
| `/rd move <名前>` | 杖で選んだ場所へラジオを移動する |
| `/rd tp <名前>` | ラジオの場所へテレポートする |
| `/rd radiolist` | 作成済みのラジオを一覧表示する。名前をクリックするとテレポートする |

### 杖

- 見た目は普通の棒（`STICK`）にエンチャントの光だけを付けたもの。1.20.1 では、隠しエンチャント（`LURE` ＋ `HIDE_ENCHANTS`）で光を再現する。
- 表示名は「ラジオ設置の杖」。ほかの棒と区別するため、アイテムの PersistentDataContainer に目印を持たせる。
- ブロックを右クリックすると、そのブロックの上面中央が設置位置として選ばれる。選択はプレイヤーごとに持ち、ログアウトで破棄する。選んだ位置にはパーティクルで目印を出す。
- 位置を選ばずに `create` / `move` を実行したら、「杖で場所を選んでください」と表示する。

### 名前のルール

- ラジオ名はサーバー内で重複不可。空白は使えない。英数字・日本語・`_`・`-` を許可する。
- `<名前>` は Tab 補完に対応し、`radiolist` の名前はクリックで `/rd tp <名前>` を実行する。

### 見た目

ラジオの見た目は、BDEngine（bdengine.app）で作ったモデルを使う。BDEngine のモデルは Display Entity の組み合わせなので、リソースパックは要らず、mod を入れていないプレイヤーにも同じように見える。

1. BDEngine でラジオのモデルを作り、「Export to Minecraft」でデータパック（zip）を書き出す。
2. zip の中にある `create.mcfunction` を、plugin のフォルダの `models/` に置く（例: `models/luxuryboombox.mcfunction`）。
3. `create` と `move` のとき、plugin がそのファイルのコマンドを上から順に、設置位置で実行する。複数のラジオを同時に作らないよう、1台ずつ順番に行う。
4. 実行が終わったら、出てきたパーツをモデルの目印タグで集め、目印タグを外して、ラジオIDを持たせる。`delete` のときは、そのラジオIDのパーツだけを消す。データパックの `delete` は、同じ名前のモデルを全て消してしまうので使わない。

モデルのファイルが未設定のときは、次の簡易モデルを使う。

| パーツ | 種別 | 素材の目安 | 役割 |
| --- | --- | --- | --- |
| 本体 | BlockDisplay | `DARK_OAK_PLANKS` を横長に変形 | ラジオの箱 |
| スピーカー | BlockDisplay | `IRON_TRAPDOOR` を前面左に | 格子状の面 |
| ダイヤル | BlockDisplay | `LIGHT_GRAY_CONCRETE` を前面右に2つ | 飾り |
| ランプ | BlockDisplay | `REDSTONE_LAMP` | 再生中は点灯（`lit=true`）、停止中は消灯 |
| アンテナ | BlockDisplay | `END_ROD` を上に伸ばして少し傾ける | 飾り |
| 名前表示 | TextDisplay | — | 1行目にラジオ名。再生中は2行目に曲名を出す |

- 名前表示は、モデルとは別に plugin が `TextDisplay` で出す。1行目にラジオ名、再生中は2行目に曲名を出す。
- 向きは、各パーツの変形行列に、モデルの中心まわりの回転をかける方式を第一案にする。設置したプレイヤーのほうを向け、90度単位に丸める。モデルの原点と前面の向きは、フェーズ5の最初に実機で確かめる。
- 1台あたりのパーツ数が多いモデルがあるので、ラジオの台数を増やしたときの負荷をフェーズ5で測る。パーツの表示距離（view range）を短くして軽くする。
- 全パーツに、所属するラジオIDを PersistentDataContainer で持たせる。パーツが消えている場合（チャンクの再読み込み時など）は、保存データから作り直す。
- 見た目の生成処理は1つのクラスに分けておく。

## 6. /radioplayer（/rp）

`/ps` と同じ操作を、ラジオ1台ごとに行うコマンド。最初の引数でラジオ名を指定し、そのラジオの位置から音が鳴る。再生ルールは「3. 再生の共通仕様」と同じ。

| 構文 | 動作 |
| --- | --- |
| `/rp <ラジオ名> play <URL>` | そのラジオのキューを空にして、URLを1曲として再生する |
| `/rp <ラジオ名> play <URL> loop` | 同じ曲を繰り返し再生する |
| `/rp <ラジオ名> play` | 現在のトラックを最初から再生する |
| `/rp <ラジオ名> playlist <URL>` | プレイリストを順番に再生する |
| `/rp <ラジオ名> playlist <URL> loop` | プレイリスト全体を繰り返し再生する |
| `/rp <ラジオ名> add <URL>` | そのURLの曲を、ラジオのキューの後ろに足す。プレイリストのURLなら、中身を順番に足す。キューが空か停止中なら、足した曲から再生を始める |
| `/rp <ラジオ名> pause` | 一時停止と再開を切り替える |
| `/rp <ラジオ名> stop` | 再生を止め、キューを空にする |
| `/rp <ラジオ名> list` | そのラジオのキューをチャットに表示する |
| `/rp <ラジオ名> list score` | そのラジオのキューをスコアボードに表示する |
| `/rp <ラジオ名> skip` | 次の曲へ進む |
| `/rp <ラジオ名> previous` | 1つ前の曲を再生する |
| `/rp <ラジオ名> keep` | そのラジオの再生内容を、サーバーを再起動しても残すかどうかを切り替える |

### ラジオ再生の挙動

- ラジオごとに独立した再生状態（キュー・位置・loop）を持つ。複数のラジオを同時に鳴らせる。`/ps` の再生とも同時に鳴らせる。
- ラジオの音は3Dサウンドにする。mod は OpenAL の音源をラジオの座標に置き、聞く側の位置と向きに合わせて、左右・前後の聞こえ方が変わるようにする。
- 距離が離れるほど音は小さくなり、聞こえる範囲の外では無音になる。範囲の初期値は24ブロック案で、設定（`radio-range`）で変えられる。
- 3D の効果を出すため、mod はデコードした音声をモノラルにまとめて再生する。ステレオのままだと、位置が音に反映されない。
- ドップラー効果、壁や障害物による音のこもり、ラジオの向きによる指向性は付けない（初期案）。
- `/ps` の再生（個人・共有）は3Dにせず、普通のステレオで鳴らす。
- 範囲の外にいるラジオは、mod が音声の取得を止める。範囲に入ったら、サーバーが管理する現在位置へ合わせて再開する。
- ラジオを移動したときは、plugin が新しい座標を `MOVE` で送る。撤去したときは `STOP` を送り、そのラジオの再生状態も破棄する。
- `<ラジオ名>` は Tab 補完に対応する。存在しない名前なら「そのラジオはありません」と表示し、ラジオ一覧を案内する。
- `keep` を付けたラジオは、キュー・何曲目か・loop・再生中／一時停止中／停止中を保存する。再生位置（何分何秒か）は保存しないので、再起動後は今の曲の頭から再開する。
- `keep` を付けたラジオは、再起動後にサーバーが起動したら自動で再生を再開する。`keep` を付けていないラジオは、再起動すると停止状態から始まる。

## 7. 保存データ・設定・権限

ラジオの場所と名前に加えて、`keep` を付けたラジオの再生内容（キュー・何曲目か・loop・再生状態）も保存し、再起動後も残す。再生位置（何分何秒か）は保存しない。`keep` を付けていないラジオと、`/ps` の再生は、再起動すると停止状態から始まる。

### 保存するデータ

| ファイル | 内容 |
| --- | --- |
| `radios.yml` | ラジオID（UUID）・名前・ワールド・座標・向き・`keep` の有無。`keep` ありのラジオは、キュー・何曲目か・loop・再生状態も保存 |
| `config.yml` | 下の設定項目 |
| `models/` | BDEngine のデータパックから取り出した `create.mcfunction` を、モデルごとに置くフォルダ（例: `models/luxuryboombox.mcfunction`） |

### 設定項目（plugin の config.yml）

| キー | 意味 | 初期値案 |
| --- | --- | --- |
| `radio-range` | ラジオの音が聞こえる範囲（ブロック） | 24 |
| `sync-interval-seconds` | 基準時刻を再通知（`SYNC`）する間隔 | 30 |
| `start-lead-ms` | 再生を始めるとき、基準時刻を先にずらす時間（全員が同時に始めるため） | 500 |
| `announce` | 再生開始の通知先（`chat` / `actionbar` / `none`） | `actionbar` |
| `max-playlist-size` | プレイリスト展開の上限曲数 | 100 |
| `max-consecutive-errors` | 連続で失敗したら停止する回数 | 3 |

mod 側のクライアント設定は、マスター音量（0〜100%）とラジオ音のオン・オフに加えて、同期の設定を持つ。補正を始める幅（40ms）、補正をやめる幅（10ms）、速度調整の上限（±2%）、手動の補正値（ms）の4つ。

### 権限ノード

| ノード | 対象 | 既定 |
| --- | --- | --- |
| `radioplugin.ps` | `/ps` の `all`・`listen`・`leave` 以外のサブコマンド | 全員 |
| `radioplugin.ps.all` | `/ps all` と `/ps all <サブコマンド>`（共有を始める・共有を操作する） | 全員 |
| `radioplugin.ps.listen` | `/ps listen`・`/ps leave`（共有を聞く・やめる） | 全員 |
| `radioplugin.rd.manage` | `/rd` の wand・create・delete・move | op のみ |
| `radioplugin.rd.tp` | `/rd tp` | op のみ |
| `radioplugin.rd.list` | `/rd radiolist` | 全員 |
| `radioplugin.rp` | `/rp` の全サブコマンド（`keep` を含む） | op のみ |

### 安全面

- plugin が取得するURLは `http` / `https` のみ許可し、`localhost` や社内ネットワークのアドレス（`127.*`、`192.168.*`、`10.*` など）は拒否する。サーバーから内部ネットワークへ接続させないため。
- 音声を取りに行くのは各プレイヤーの mod なので、再生するURLの配信元には、プレイヤーのIPアドレスが見える。この点は導入時の注意書きに入れる。

## 8. プロジェクト構成と依存

mod（Gradle）と plugin（Maven）は別々のプロジェクトにし、通信メッセージの定義だけを `docs/protocol.md` に1つ置いて、両側の実装がそれを参照する。

```text
radiomod-plugin/
├─ mod/        Forge 1.20.1（Gradle・ForgeGradle）
│  └─ src/main/java/…/
│     ├─ RadioMod.java     エントリポイント
│     ├─ net/              チャンネル登録・メッセージ処理
│     ├─ audio/            LavaPlayer での取得・デコード、OpenAL での再生
│     └─ sync/             位置合わせ・範囲判定・距離減衰
├─ plugin/     Spigot 1.20.1（Maven）
│  └─ src/main/java/…/
│     ├─ RadioPlugin.java  エントリポイント
│     ├─ command/          /ps・/rd・/rp
│     ├─ player/           再生エンジン（キュー・状態・loop）
│     ├─ radio/            ラジオ管理・Display Entity・杖
│     └─ net/              メッセージの送受信
└─ docs/protocol.md        メッセージ定義（唯一の正）
```

| 項目 | mod | plugin |
| --- | --- | --- |
| ビルド | Gradle（ForgeGradle）、Java 17 | Maven、Java 17 |
| 本体API | Forge 1.20.1（47.x） | Spigot API 1.20.1（`provided`） |
| 音声ライブラリ | LavaPlayer と youtube-source を jar-in-jar で同梱 | LavaPlayer と youtube-source を maven-shade-plugin で同梱（パッケージ名を付け替える） |
| 出力 | mod の jar を各プレイヤーが `mods/` に入れる | plugin の jar をサーバーの `plugins/` に入れる |

- 名前は決まっている。modid は radiomod、plugin 名は radioplugin、groupId は com.oogata、パッケージは com.oogata.radiomod と com.oogata.radioplugin、作者は oogata。
- LavaPlayer と youtube-source のリポジトリ・版は、実装時に公式の README で最新の安定版を確認して固定する（この仕様書では確認していない）。
- mod の再生は、OpenAL のソースを mod 自身で作って PCM をストリーミングする方式を第一案にする。Minecraft 標準のサウンドエンジンに独自の音声ストリームを渡す方式が第二案で、フェーズ2の検証で選ぶ。

## 9. 実装フェーズ

7つのフェーズに分け、1フェーズずつ AI に頼む。各フェーズの完了条件を実機で確認してから次へ進む。AI には、毎回この仕様書の該当する節と、直前までのコードを渡す。

1. **通信の疎通**: mod が接続時に `HELLO` を送り、plugin がそれを受け取る。plugin から送ったテスト用メッセージを mod が受け取る。
   - 完了条件: mod 入りのクライアントで Spigot サーバーに入ると、plugin のログに `HELLO` が出て、mod 側のログにテスト文字列が出る。ここで通信が通らなければ、以降の設計を見直す。
2. **mod 単体の音声再生**: デバッグ用のクライアントコマンドで、URL の再生・停止・一時停止ができる。
   - 完了条件: mp3 の直リンクとインターネットラジオのURLが鳴り、止められる。
3. **`/ps` の基本（play・stop・pause）と同期**: plugin がプレイヤーごとの再生状態を持ち、そのプレイヤーの mod へ同期する。時計合わせ（TIME\_REQ・TIME）と、基準時刻による位置合わせも、ここで入れる。
   - 完了条件: 自分が打った再生が自分にだけ鳴る。2人が別々の曲を同時に流せる。
4. **`/ps` の残り機能**: playlist・add・loop・skip・previous・list・list score・`all`、YouTube の対応。
   - 完了条件: 「3. 再生の共通仕様」の再生ルールどおりに動く。`/ps all` で共有のお知らせが届き、聞くを選んだ人に同じ位置の音が、100ms 以内のずれで鳴る。聞くのをやめる・また聞くも動く。/ps all skip など、共有の操作も動く。
5. **ラジオの設置と管理（`/rd`）**: wand・create・delete・move・tp・radiolist、BDEngine モデルの読み込み、保存と復元。
   - 完了条件: BDEngine で作ったモデルがラジオとして設置され、向きが正しい。再起動後もラジオが残り、パーツが欠けていたら作り直される。`radiolist` のクリックでテレポートできる。
6. **`/rp` と距離減衰、`keep`**: ラジオごとの再生、位置のある音、範囲外での取得停止、移動と撤去への追従、再起動後の再開。
   - 完了条件: ラジオに近づくと大きく、離れると小さくなる。ラジオの右を通ると右から、背を向けると後ろから聞こえる。2台のラジオで別々の曲が鳴る。`keep` を付けたラジオだけが、再起動後に自動で鳴り始める。
7. **仕上げ**: 音量スライダー、エラー表示、権限、設定ファイル、導入手順の README。
   - 完了条件: 音量スライダーで「音楽」と「ラジオ」の音量を別々に変えられる。権限のないプレイヤーがコマンドを使えず、mod 未導入のプレイヤーも問題なく参加できる。

## 10. 未決事項とリスク

### 決めたいこと

- 現在、決めたいことはありません。

### リスク

- **YouTube**: 規約に触れる可能性があり、YouTube 側の仕様変更で突然動かなくなりうる。主な音源はインターネットラジオと直リンクと考え、YouTube は付加機能として扱う。
- **曲の権利**: 配信や録画に音が入る場合は、権利を確認できる音源を使う。
- **通信の疎通**: Forge 1.20.1 の通信チャンネルが Spigot サーバーと通じるかは未検証。フェーズ1で最初に確かめる。
- **BDEngine モデルの扱い**: 出力された `/summon` コマンドを plugin から実行したときの向きや原点の扱いは未検証。パーツ数が多いモデル（例: 約600個）を何台まで置けるかも、あわせて確かめる。フェーズ5の最初に確かめる。
- **再生位置の同期**: 目標は100ms以内だが、Bluetooth ヘッドホンなど、音の出力の遅れは測れないので、プレイヤーごとに数十〜数百msずれうる。手動の補正値で調整できるようにする。ライブ配信（インターネットラジオ）は、位置の同期ができない。
- **クライアントの負荷**: ラジオを同時に何台も鳴らすと、CPU とメモリを使う。範囲外では取得を止めて軽くする。
- **対応範囲**: mod は Forge 専用で、Fabric と NeoForge には対応しない。plugin は Spigot 向けで、Paper でも動かす想定だが、実機で確認が必要。
